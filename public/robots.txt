# One group for all crawlers. Per the robots.txt spec a crawler obeys only its
# most specific matching group — earlier bot-specific Googlebot/Bingbot groups
# were silently CANCELLING these rules for exactly the two bots that matter.
#
# User pages (/profile, /saved, /recent) and auth pages (/login, /signup) are
# excluded via `robots: noindex` metadata instead of a crawl block: Google can
# only see a noindex directive on pages it is allowed to crawl.

# `Disallow: /_next/` on its own blocked every stylesheet, JS chunk and font on
# the site — they are all served from /_next/static/. Google renders a page to
# index it, and a crawler that cannot fetch the CSS renders it unstyled, which
# Google explicitly warns "directly harms how well our algorithms render and
# index your content". That mattered little while the pages were empty client
# shells; now that /listings, every listing detail page and the GTA pages are
# server-rendered, it was throwing away the value of that work on ~2,500 pages.
#
# Per the spec Google applies the MOST SPECIFIC matching rule, so the longer
# `Allow: /_next/static/` beats `Disallow: /_next/` for assets while build
# internals stay blocked. /_next/image is the image optimizer — allowed so
# optimized images stay eligible for Google Images as raw <img> tags migrate
# to next/image.
# /api/blog-cover is the generated og:image + Article JSON-LD image for every
# blog post without a stored cover (see lib/blog-cover.js). `Disallow: /api/`
# alone blocked Googlebot-Image from fetching it, killing article thumbnail /
# rich-result eligibility for most of the blog — same most-specific-rule-wins
# technique as the /_next/static/ carve-out below.
User-agent: *
Allow: /
Disallow: /api/
Allow: /api/blog-cover
Disallow: /admin/
Disallow: /admin.html
Disallow: /_next/
Allow: /_next/static/
Allow: /_next/image

# Crawlers that take and never give back.
#
# WHY (measured 2026-08-04): six hours of production logs showed 972 requests to
# /listings/[id] — the top page route on the site by a wide margin, ~20x the
# homepage. Every entry was a DIFFERENT listing id, spanning all TREB region
# prefixes (W/C/E/N/S/X), in a steady ~162/hour walk. Nobody browses that way;
# something is walking the sitemap end to end. The page itself is already as
# cheap as it can be (ISR at 900s, one upstream call cached to match), so the
# only lever left is who is allowed to walk it.
#
# EVERY GROUP BELOW IS A FULL DISALLOW, AND THAT IS THE ONLY REASON IT IS SAFE
# TO NAME A BOT HERE. A crawler obeys only its most specific matching group, so
# adding `User-agent: Googlebot` — even to grant it something — would silently
# cancel the `*` rules above for the one bot that matters. That exact bug has
# already been fixed on this file once; see the header comment. Never add a
# named group for a crawler you want to keep.
#
# DELIBERATELY STILL ALLOWED, because they can send a real investor:
#   Googlebot, Bingbot, Applebot (Siri/Spotlight), DuckDuckBot, Slurp — search.
#   OAI-SearchBot, ChatGPT-User, PerplexityBot, Claude-User — AI *search*, which
#     cites and links back. These are not the training crawlers of the same
#     brands, which is why GPTBot and ClaudeBot appear below and these do not.
#   Applebot is allowed while Applebot-Extended is blocked: the plain one feeds
#     Siri and Spotlight, the -Extended suffix is Apple Intelligence training.
#   Google-Extended is blocked and this costs nothing in Search — it gates
#     Gemini training only. Indexing and AI Overviews both ride Googlebot.
